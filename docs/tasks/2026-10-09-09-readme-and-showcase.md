## 目标

## README 结构

1. **标题与一句话**：开口（Kai-Kou）——PTE 口语练习平台；RA 朗读题基于真实录音逐词诊断，每个问题可回听核验。附正式网站链接、CI 徽章。
2. **一张图**：结果页手机截图（逐词标注 + 指标 + 建议）。用现有 `output/playwright/` 中的生产截图，或重新截一张清晰的；放到 `docs/images/`（压缩后单张 ≤ 300KB）。**截图中不能出现邮箱、用户 ID 等个人信息。**
3. **问题**：旧方案是"浏览器语音识别 → LLM 读文字打分"。用真实例子说明：同一段录音（RA_023），浏览器识别完整度 84%、标出 9 处问题，而 Whisper 98%、1 处；旧方案给出内容分 58。另：同水平朗读因主备模型不同，总分相差约 20 分（6 次练习观察，样本小，写明）。
4. **方案**：Mermaid 流程图：录音 → 浏览器端能量检测停顿 → 上传私有存储 → Groq Whisper 词级时间戳 → 与原文逐词对齐（数字/同音词/复合词/英美拼写归一化）→ 停顿分类与语速 → 证据列表 → 结果页标注与回听 → 重录对比。
5. **设计取舍**（每条 2–3 句，这是面试重点）：
   - 代码负责判断，模型不打分：不再展示发音分和 10–90 总分。
   - 识别不确定不下结论：同音词、低置信度不算用户错误；替换类只说"可能读错或识别不清，请回听"。
   - 方案 A（通用识别）而非按原文发音评估：成本与依赖更低；代价见评测。
   - Whisper 时间戳会吸收停顿 → 停顿改由音频能量检测。
   - LLM 练习建议：设定门槛后 3 轮评测未达标（最终通过率 33%，与模板相同 78%），按预先定好的规则改用确定性模板，代码保留。
6. **评测**（数字照抄 `docs/ra-diagnosis-eval.md`，不得改写或取整到更好看）：
   - 表格：浏览器 vs Whisper 的报错精确率、召回率、误报数、位置准确率。
   - 一句话结论：误报 34 → 2，精确率 27.7% → 71.4%；召回率 38.5%，漏报的 8 处 Whisper 转写与原文相同，文本对齐无法发现。
   - 局限：单一说话人、48 个位置、候选由两套识别挑选。链接完整报告。
   - 停顿检测：注明"待构造样本验证"（录音完成后再更新）。
7. **工程**：主备模型切换规则修复（覆盖 401/402/403/404/500）；结果服务端写库、`attempt_id` 幂等；评分与诊断版本记录；功能开关 + 预览验收 + 审查后发布；CI 双构建；数据库保活。每项一行。
8. **技术栈**：Vue 3、Vite、Tailwind、Vercel Serverless、Supabase（Postgres / Storage / RLS）、Groq Whisper、Node `node:test`。
9. **本地运行**：保留现有内容，补充 `ffmpeg` 仅评测脚本需要。
10. **局限与下一步**：召回率偏低 → 按原文的发音评估；推广到 RS / DI / RTS；学习者错误模型。
