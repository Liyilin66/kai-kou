## 目标

结果页在证据和指标之外，给出 1–3 条**能执行的练习建议**。每条建议都必须引用具体证据（可以点开回听），不允许出现证据里没有的问题。

原则：**代码负责判断，LLM 只负责把证据说成人话。**

## 设计

### 1. 生成时机：异步，不拖慢诊断

`/api/ra/analyze` 现在约 3 秒返回证据，保持不变。结果页拿到证据后，再调用同一接口的新动作：

```
POST /api/ra/analyze  { action: 'feedback', attempt_id }
```

沿用影子评分的写法：按 `attempt_id` 查记录 → 条件更新占位（防止并发重复生成）→ 生成 → 保存 → 返回。已有结果时直接返回，不重复调用模型。

### 2. 模型

- 主：Groq `openai/gpt-oss-120b`（实测约 1 秒）；备：现有 OpenAI 兼容中转。复用 `backend/llm/provider-error.js` 的切换规则。
- 记录实际使用的 `provider`、`model`、`prompt_version`（`ra-feedback-0.2`）。

### 3. 新模块 `backend/speech/feedback.js`

输入：证据列表（按严重程度取前 6 条）、指标、原文。**不传识别文本全文**，避免模型绕过证据自行发挥。

输出 JSON：

```json
{
  "summary": "一句话总体情况（中文，≤ 60 字）",
  "suggestions": [
    { "evidence_ids": ["E1", "E3"], "issue": "问题描述（≤ 40 字）", "action": "具体练习动作（≤ 60 字）" }
  ]
}
```

提示词要求：

- 中文，教练口吻；1–3 条建议，按重要性排序。
- 每条建议至少引用 1 个证据编号。
- 替换类证据只能说"可能读错或识别不清，建议回听"，**禁止**下发音结论。
- 不出现任何分数、"PTE 分"、"发音分"。
- 没有证据时：`suggestions` 为空数组，`summary` 根据指标给出一句肯定 + 一个保持方向（例如语速是否合适）。

### 4. 校验器（同文件导出，纯函数）

逐项检查，不通过就把具体原因附在提示词后**重试一次**；仍不通过则使用**模板反馈**（由证据直接生成，不调用模型）：

- JSON 结构与字段长度
- 建议数量 0–3；有证据时至少 1 条
- 引用的证据编号全部存在
- 文本不含禁用词：`发音错误`、`发音不准`、`分数`、`分`（紧跟数字时）、`PTE`
- `issue` 提到的问题类型与所引用证据的类型一致（例如引用的是停顿证据，`issue` 里不能说成漏读）

模板反馈示例：漏读 → "第 N 句漏读了 X，回听后放慢该处重读一遍"；长停顿 → "在 X 前停顿了 2.3 秒，先把这一句连读三遍"。

### 5. 存储

追加 SQL（用户在 Supabase 执行一次）：

```sql
alter table public.speech_analyses
  add column if not exists feedback jsonb,
  add column if not exists feedback_status text check (feedback_status in ('processing','done','failed')),
  add column if not exists feedback_meta jsonb;
```

`feedback_meta` 存 `provider`、`model`、`prompt_version`、`attempts`（第几次通过 / 是否用了模板）、`latency_ms`。

同时把 `summary` 写入对应 `practice_logs.feedback`，让 AI 私教读取练习历史时能看到。

### 6. 结果页

- 在指标卡片下方新增"练习建议"卡片：加载中显示占位；失败时显示模板反馈，不显示报错。
- 每条建议下方列出引用的证据小标签，点击 → 播放器跳到对应位置（复用 `evidencePlaybackSeconds`）。
- 页面底部的版本小字加上反馈模型。

## 审查结果（Claude，2026-10-08）

**结论：工程部分通过（SQL、原子保存、幂等占位、异步生成、校验器结构都正确），但"AI 建议"这一层目前没有产生价值，不合并，需要返工。**

### 主要问题：100% 首次通过率是靠"让模型照抄模板"得到的

`buildPrompt` 里有这几条要求：

- "issue 使用下方示例提供的表述……不要换成新的问题标签"
- "summary 使用'先回听标记位置，再按下面的建议练习。'"
- "每条建议仅引用一个 evidence_id"
- 示例本身就是 `buildTemplateFeedback` 的输出

结果是：任务文档里的两条样本，模型输出和模板**逐字相同**。也就是说，花一次模型调用，得到的是不调用模型也能生成的内容。通过率 100% 不说明建议好，只说明模型学会了抄。这正是任务说明里"达不到就先改提示词，不要放宽校验"想避免的反面——方向反了：不是放宽校验，而是把生成收紧到没有意义。

另外，校验器要求"英文词只能来自所引用证据"，这让模型无法说出"把 *carrying spices, perfumes and objects* 这半句连起来慢读"这类真正有用的练习动作，只能写泛泛的"回听后再读一遍"。

### 返工要求

1. **提示词**：删除上面四条照抄指令。示例只用来说明 JSON 结构，内容换成与输入无关的虚构例子。允许一条建议引用多个**同类型且在同一句**的证据；允许 summary 归纳规律（例如"两处问题都在长句后半段"），但只能提到证据中存在的问题类型（现有校验保留）。
2. **放开英文词来源**：允许使用所引用证据所在**原文句子**中的英文词（按原文句号、问号、感叹号切句），其他词仍然禁止。这样模型可以给出"把某半句连读"的具体动作，又不能凭空编造原文没有的词。
3. **其余校验全部保留**：证据编号存在、类型一致、替换类必须"可能……/回听"、禁用发音/分数/PTE、禁止自行描述时长。
4. **评测增加"是否有增量价值"指标**：`eval-feedback.js` 统计每条建议的 `action` 与模板 `action` 是否相同（去掉标点后比较），输出"与模板相同比例"。
   **新门槛：首次通过率 ≥ 80%，最终 ≥ 95%，且与模板相同的建议 ≤ 20%。**
5. **如果改完后达不到门槛**：不要再收紧提示词去凑数字，直接在交付说明里报告实际数字。届时再决定是保留 LLM 还是只用模板——两种都可以接受，但要基于真实数据决定。

### 顺手修复：复合词被拆开或合并时误判（`align.js`）

实测（真实样本 `ra-real-0002` 就命中了第一条）：

| 原文 | 识别 | 当前结果 | 期望 |
|---|---|---|---|
| `streetlights` | `street lights` | 多读 street + 替换 | match |
| `classroom` | `class room` | 替换 + 多读 | match |
| `every day` | `everyday` | 替换 + 漏读 | match |

规则：一侧相邻两个词拼接后与另一侧一个词完全相同（归一化后），视为匹配；时间范围取两个词的并集。`water first` ↔ `waterfront` 不满足拼接相等，仍判为错误（这是正确的）。为上表三行加测试，并确认 RA_024 的结果不变。

如实报告数字、没有为凑门槛再收紧提示词，这一点做得对。复合词对齐修复已复核通过。但"33% 首次通过"这个结论本身不可靠，原因如下。

### 1. 失败主要来自校验器误杀，而不是模型乱写

逐条看 `output/eval/feedback-*.json` 的失败原因：

- 7 次失败中有 6 次包含 **`action 必须是 1–60 字`**。长度用 `Array.from(text).length` 计算，**英文每个字母算一个字**。一句"先单独练习句首 The training of an actor，连读三遍……"就有 57 个字符，而这恰恰是我们希望模型写出的"引用原文半句"的具体动作。返工放开了英文词来源，却没调整长度计算，两条规则互相打架。
- 其余失败是模型写了"发音"等禁用词——这是真实的模型违规，校验器拦得对。

### 2. 两次运行结果差异极大，6 个样本不足以下结论

同一配置的两次运行（`06-01-23` 与 `06-01-26`）：首次通过率 33% 对 67%，最终通过率 33% 对 100%，与模板相同比例 83% 对 0%。而且通过的建议质量明显高于模板（例如 `ra-real-0004` 给出了具体的半句连读练习）。

### 3. 模型调用异常被静默吞掉

`generateEvidenceFeedback` 里 `catch { return fallback(attempt); }` 不记录异常原因。一次运行中有样本切到中转并耗时 33–44 秒，说明 Groq 调用失败过（多半是两次运行并发触发限流），但报告里看不出来。

### 最后一轮修改（只做这三项）

1. **长度按"中文字 + 英文单词"计**：每个英文单词计 1，中文每字计 1；`issue` 上限 40、`action` 上限 60、`summary` 上限 60 保持不变。
2. **模型异常写入 `validation_failures`**（记录 `provider_error` 和错误类型），回退模板的原因在报告中可见。
3. **评测改为连续跑 3 轮（串行，不并发）**，报告每项指标的平均值和最小～最大范围。
